<h3 id="1">[1] NPLSD: Accelerating Line-Segment Detection on NPU Microcontrollers</h3>
- **arXiv**: [2609.25022](https://arxiv.org/abs/2609.25022)
- **Authors**: Parsa Hassani Shariat Panahi, Amir Hossein Jalilvand, M. Hassan Najafi
- **Subjects**: cs.AR; cs.CV
- **Tags**: Edge Computing, Object Detection
- **Summary**: 该论文针对基于Transformer的线段检测器难以部署在微控制器上的问题，指出注意力、网格采样和归一化等算子与卷积导向的NPU架构不匹配，且解码器自注意力会产生39 MB的分数张量超出片上内存。作者提出NPLSD设计方法，构建两个NPU兼容检测器：NPLSD-H用全卷积特征金字塔和F-Clip密集头替换Transformer头，NPLSD-M适配M-LSD-tiny主干。在ShanghaiTech Wireframe上，2.63M参数的NPLSD-H达到sAP^10=37.9（int8为35.9），0.62M参数的NPLSD-M达到41.9（int8为41.1）。

<h3 id="2">[2] GRADE-RTL: Evaluating LLM-Generated RTL Beyond Compilation</h3>
- **arXiv**: [2609.25335](https://arxiv.org/abs/2609.25335)
- **Authors**: Hepziba Susan, Shivaranjani G. R., Malik Imran, Muhammad Rashid, Sumathi Gokulanathan, Zain Ul Abideen
- **Subjects**: cs.AR; cs.PL
- **Tags**: RTL Generation, LLM Evaluation
- **Summary**: 该论文指出仅凭编译成功无法保证LLM生成RTL代码的结构完整性、功能正确性和实现效率，因此提出GRADE-RTL评估框架。该框架通过端口签名、编译、精化、模块完整性和功能等价性五项检查，在十个边缘相关IP设计上评估了九种通用及RTL专用LLM。结果显示端到端成功率在0%到70%之间，失败原因包括层次解析、逻辑不完整和行为不匹配；FPGA实现和65 nm ASIC综合进一步表明功能等价的RTL在资源、时序、面积和功耗上差异显著。

<h3 id="3">[3] Accelerating the Mitigation of LLM Inference Nondeterminism Across GPU Architectures</h3>

- **Subjects**: cs.AR; cs.LG
- **Tags**: LLM Inference, GPU Computing
- **Summary**: 该论文针对LLM在贪心解码下跨GPU架构输出不可复现的问题，指出其根源是浮点非结合性与硬件相关的内核选择导致舍入差异翻转输出token。作者提出一组固定配置的融合上采样GEMM内核，从内存加载16位权重、在寄存器中上采样为FP32，并按仅取决于问题形状的归约顺序进行IEEE-754累加。实验确认线性层输出在NVIDIA Ampere、Ada和Hopper GPU上逐位相同，端到端速度比现有最优方案快1.17至3.1倍，并将权重内存流量减半。

<h3 id="4">[4] Hot-Cold Tiering of HBM and High Bandwidth Flash for Agentic LLM Serving</h3>
- **arXiv**: [2609.25782](https://arxiv.org/abs/2609.25782)
- **Authors**: Jongjin Baek, Won Ji, Seungjae Yoo, Joo-Young Kim
- **Subjects**: cs.AR
- **Tags**: LLM Serving, Memory Architecture
- **Summary**: 该论文针对智能体式LLM服务中多轮会话空闲时仍需保留完整上下文、而GPU内存容量有限导致KV状态被驱逐的问题，提出利用高带宽闪存（HBF）作为冷层。分析发现智能体KV状态具有冷热分离的访问模式：小热集每步解码都被读取，大冷池仅在会话恢复时读取。作者将热集放在HBM、冷池放在HBF，形成GPU内存层内的冷热KV层次结构。在Qwen3-Coder-30B-A3B上，该设计实现14 ms的TBT、仅增加约0.1 ms恢复延迟，每GPU可承载24倍并发会话，并每8-GPU节点降低7.6 kW读取功耗。
